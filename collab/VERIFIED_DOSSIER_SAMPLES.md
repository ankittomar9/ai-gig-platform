#### Round 2: Domain Deep-Dive
**Question:** *In a post-training data pipeline handling millions of instruction-tuning pairs, how would you design a validation filter to catch corrupted tokens or malformed JSONL records without tanking throughput?*

**Winning Answer Formulation:**
> I'd use a streaming validator using schema verification (like Pydantic or FastJSON) at the ingestion boundary rather than loading whole batches into memory. I'd set up dead-letter queues for unparseable records so the pipeline doesn't crash, and emit metrics for error rates to catch data drifts early.

#### Round 3: Quality & Evaluation
**Question:** *When preparing training datasets, how do you handle deduplication and synthetic dataset contamination?*

**Winning Answer Formulation:**
> I apply MinHash with LSH (Locality Sensitive Hashing) for fuzzy near-deduplication to prevent the model from memorizing identical phrasings. For contamination, I cross-reference evaluation benchmark splits against training corpora using strict n-gram matching.

#### Round 4: Edge Cases & Scenarios
**Question:** *A data pipeline node crashes halfway through an 8-hour preprocessing job. How do you design your jobs to be idempotent and recoverable?*

**Winning Answer Formulation:**
> Every batch step must be atomic and state-checkpointed. By storing watermarks or processed batch UUIDs in a persistent datastore, a restarted worker simply resumes from the last confirmed watermark without reprocessing or duplicating records.
